# AD-TR-01 — Phase 2E-3 — Production Contract Boundary

## 1. Latar Belakang

Phase 2E-2 menemukan bahwa Recognition Knowledge sebaiknya tetap merupakan script-specific knowledge.

Namun Generic Recognition Engine tetap membutuhkan akses terhadap knowledge tersebut.

Hal ini menimbulkan pertanyaan arsitektural:

> Bagaimana Generic Core memperoleh Recognition Knowledge tanpa bergantung pada struktur internal ScriptPack?

Phase ini berfokus pada contract boundary.

Bukan pada nama method atau class.

---

# 2. Tujuan

Phase 2E-3 bertujuan untuk:

1. memisahkan Generic Core dari struktur internal ScriptPack;
2. menentukan informasi minimum yang dibutuhkan Recognition Engine;
3. mengidentifikasi ownership Recognition Knowledge;
4. mengidentifikasi kebutuhan validation;
5. menentukan batas konseptual production contract.

---

# 3. Masalah Coupling

Generic Recognition Engine seharusnya tidak secara langsung mengetahui struktur internal seperti:

```python
characters = scriptpack.characters
candidates = scriptpack.recognition_candidates
```

Karena Generic Core kemudian bergantung pada nama dan struktur internal ScriptPack.

Apabila ScriptPack berubah:

```text
characters
    ↓
character_registry
```

Generic Core dapat ikut terdampak.

Prinsip yang ingin dipertahankan:

```text
Generic Core
        ≠
ScriptPack Internal Structure
```

---

# 4. Contract-Oriented Interaction

Generic Core tidak perlu bertanya:

> Bagaimana ScriptPack menyimpan Character Data?

Generic Core hanya membutuhkan:

> Berikan Recognition Knowledge yang sesuai dengan contract.

Model konseptual:

```text
Generic Core
      │
      │ request capability
      ▼
ScriptPack-facing Boundary
      │
      │ provide normalized knowledge
      ▼
Recognition Engine
```

Dengan demikian internal ScriptPack dapat berubah selama contract yang diberikan tetap terpenuhi.

---

# 5. Minimum Recognition Pattern Contract

Berdasarkan Phase 2E-1, Recognition Engine minimal membutuhkan setiap pattern untuk membawa:

```text
value
classification
```

Contoh:

```text
ka  → KNOWN_COMPLETE_PATTERN
nga → KNOWN_COMPLETE_PATTERN
ng  → RECOGNITION_CANDIDATE
ny  → RECOGNITION_CANDIDATE
```

Recognition Engine tidak membutuhkan informasi seperti:

```text
glyph
unicode
description
```

untuk melakukan basic pattern recognition.

---

# 6. Normalized Recognition Knowledge

Script-specific internal data dapat memiliki bentuk yang berbeda.

Namun sebelum digunakan oleh Generic Recognition Engine, informasi tersebut secara konseptual harus menjadi:

```text
Normalized Recognition Knowledge
```

Model:

```text
ScriptPack Internal Data
          ↓
Knowledge Boundary
          ↓
Normalized Recognition Knowledge
          ↓
Generic Recognition Engine
```

Normalisasi berfungsi sebagai boundary antara:

```text
Script-specific representation
```

dan:

```text
Generic recognition algorithm
```

---

# 7. Recognition Knowledge Provider Concept

Untuk keperluan analisis, digunakan konsep:

```text
Recognition Knowledge Provider
```

Istilah ini belum merupakan keputusan nama production class atau API.

Concept ini hanya menggambarkan sebuah tanggung jawab:

> Menghasilkan Recognition Knowledge dalam bentuk yang dapat digunakan Generic Recognition Engine.

Provider dapat secara internal:

1. membaca Character Knowledge;
2. menurunkan Known Complete Patterns;
3. memperoleh Recognition Candidates;
4. menggabungkan keduanya;
5. melakukan normalisasi.

Generic Recognition Engine tidak perlu mengetahui langkah-langkah tersebut.

---

# 8. Knowledge Integrity

Phase ini menemukan potensi collision.

Contoh hipotetis:

```text
Character-derived Pattern:
ng → KNOWN_COMPLETE_PATTERN

Explicit Candidate:
ng → RECOGNITION_CANDIDATE
```

Hal tersebut menghasilkan:

```text
Same Value
+
Conflicting Classification
```

Generic Recognition Engine tidak seharusnya menentukan kebijakan semacam:

```text
KNOWN always wins
```

tanpa evidence dan contract yang jelas.

Sebaliknya, conflict tersebut merupakan masalah:

```text
Knowledge Integrity
```

---

# 9. Preliminary Integrity Requirements

Normalized Recognition Knowledge minimal harus memenuhi:

```text
✓ pattern value valid
✓ classification valid
✓ conflicting classification prohibited
```

Validation pada tahap ini berfokus pada:

```text
Contract Integrity
```

bukan:

```text
Linguistic Correctness
```

Generic validation tidak menentukan apakah sebuah pattern secara linguistik benar untuk suatu script.

Itu tetap merupakan tanggung jawab script-specific domain.

# 12. API Shape Tidak Diputuskan

Phase ini tidak menentukan apakah ScriptPack nantinya memiliki:

```text
get_recognition_knowledge()
```

atau:

```text
recognition_knowledge
```

atau bentuk lain.

Tidak pula diputuskan apakah boundary diwujudkan melalui:

- method;
- property;
- provider object;
- adapter;
- factory;
- registry integration.

Yang ditetapkan hanya contract principle:

> Generic Recognition Layer harus memperoleh Recognition Knowledge melalui boundary yang tidak memaksanya mengetahui struktur internal ScriptPack.

---

# 13. Contract Principle

Contract konseptual minimum:

```text
INPUT TO RECOGNITION ENGINE

Iterable Recognition Knowledge

Each Pattern:
    • value
    • classification
```

Integrity:

```text
• valid value
• valid classification
• no conflicting classification for identical pattern
```

Source:

```text
• script-specific
• opaque to Generic Core
```

---
