# AD-TR-01 — Phase 2E-2 — Recognition Knowledge Mapping

## 1. Latar Belakang

Phase 2E-1 telah menentukan capability minimum Recognition Layer.

Namun Recognition Layer tidak dapat melakukan knowledge-driven matching tanpa mengetahui pattern yang tersedia.

Pertanyaan utama pada Phase 2E-2 adalah:

> Dari mana Recognition Layer memperoleh knowledge untuk mengenali input?

Pertanyaan ini memiliki dampak langsung terhadap:

- Generic Core;
- ScriptPack;
- Character Model;
- extensibility;
- data duplication;
- future maintenance.

---

# 2. Tujuan

Phase ini bertujuan untuk:

1. mengidentifikasi jenis knowledge yang terlibat;
2. membedakan Character Knowledge dari Recognition Knowledge;
3. menentukan hubungan Recognition Candidate terhadap Character Data;
4. mengeksplorasi sumber Recognition Knowledge;
5. menghindari duplication dan Generic Core coupling.

---

# 3. Permasalahan Awal

Character Data secara konseptual memiliki informasi seperti:

```text
glyph
latin
unicode
description
```

Sebagian informasi tersebut dapat digunakan untuk membangun known recognition pattern.

Contoh:

```text
ka
na
ca
ra
nga
```

Namun eksperimen menunjukkan adanya pattern seperti:

```text
ng
ny
```

yang dapat berguna dalam recognition tanpa harus diperlakukan sebagai Character Model lengkap.

Jika semua recognition requirement dipaksakan masuk ke Character Data, muncul risiko:

```text
Recognition Requirement
        ↓
Memaksa Character Model berubah
```

Hal tersebut tidak sehat.

---

# 4. Tiga Domain Knowledge

Phase ini mengidentifikasi tiga domain konseptual.

## 4.1 Character Knowledge

Menjawab pertanyaan:

> Karakter apa yang dimiliki script?

Contoh informasi:

```text
glyph
latin
unicode
description
```

Character Knowledge adalah bagian dari representasi karakter.

---

## 4.2 Recognition Knowledge

Menjawab pertanyaan:

> Pattern apa yang dapat dikenali dalam input?

Minimal membawa:

```text
value
classification
```

Contoh:

```text
ka  → KNOWN_COMPLETE_PATTERN
nga → KNOWN_COMPLETE_PATTERN
ng  → RECOGNITION_CANDIDATE
```

---

## 4.3 Resolution Knowledge

Menjawab pertanyaan:

> Bagaimana sequence hasil recognition harus ditafsirkan?

Resolution Knowledge berada setelah Recognition.

Ia dapat menggunakan:

- sequence;
- classification;
- position;
- neighbouring units;
- script-specific orthographic rules.

---

# 5. Discovery Penting

Phase ini menetapkan pemisahan konseptual:

```text
Character Knowledge
        ≠
Recognition Knowledge
        ≠
Resolution Knowledge
```

Ketiganya dapat saling berhubungan, tetapi tidak boleh dianggap sebagai satu domain yang identik.

---

# 6. Alternatif Sumber Recognition Knowledge

## 6.1 Model A — Generic Core Menyimpan Recognition Data

Model:

```text
Generic Core
├── Recognition Engine
└── Script-specific Patterns
```

Model ini ditolak karena menyebabkan Generic Core mengetahui detail:

- Javanese;
- Balinese;
- Sundanese;
- script lainnya.

### Kesimpulan

```text
REJECTED
```

Alasan:

```text
Script-specific knowledge must not live in Generic Core.
```

---

## 6.2 Model B — Character Data Digunakan Secara Langsung

Model:

```text
Character Data
      ↓
Recognition Engine
```

Keuntungannya adalah tidak terjadi duplikasi known character pattern.

Namun model ini tidak secara alami menjelaskan Recognition Candidate yang bukan Character Data.

### Kesimpulan

Model ini berguna sebagai sumber derived knowledge, tetapi tidak cukup sebagai satu-satunya Recognition Knowledge source.

---

## 6.3 Model C — Explicit Recognition Knowledge Terpisah

Model:

```text
ScriptPack
├── Character Knowledge
└── Recognition Knowledge
```

Recognition Candidate dapat disimpan secara eksplisit.

Keuntungannya:

```text
✓ flexible
✓ candidate memiliki tempat yang jelas
✓ Character Model tidak dipaksa berubah
```

Namun terdapat risiko duplication.

Contoh:

```text
Character Data:
ka

Recognition Data:
ka
```

Perubahan pada salah satu sumber dapat menyebabkan:

```text
DATA DRIFT
```

---

# 7. Hybrid Knowledge Model

Berdasarkan evidence, model yang paling menarik untuk investigasi lanjutan adalah:

```text
Character Knowledge
        │
        │ derive
        ▼
Known Complete Patterns

Explicit Recognition Candidates
        │
        ▼

        ┌───────────────┐
        │ Recognition   │
        │ Knowledge     │
        └───────┬───────┘
                ▼
        Recognition Layer
```

Secara konseptual:

```text
Recognition Knowledge
=
Derived Known Patterns
+
Explicit Recognition Candidates
```

---

# 8. Derived Known Patterns

Known Complete Pattern dapat diperoleh dari Character Knowledge yang relevan.

Contoh konseptual:

```text
Character:
ka

Latin:
ka
```

dapat berkontribusi menjadi:

```text
ka → KNOWN_COMPLETE_PATTERN
```

Dengan pendekatan ini, data character yang sudah tersedia tidak perlu diduplikasi secara manual.

---

# 9. Explicit Recognition Candidates

Pattern seperti:

```text
ng
ny
```

dapat dideklarasikan sebagai:

```text
RECOGNITION_CANDIDATE
```

tanpa memaksa pattern tersebut menjadi Character Data.

Ini mempertahankan batas:

```text
Character Model
        ≠
Recognition Extension
```

---

# 10. Preliminary Knowledge Flow

Model konseptual yang ditemukan:

```text
                    ScriptPack
                        │
         ┌──────────────┴──────────────┐
         │                             │
         ▼                             ▼
Character Knowledge         Recognition Extensions
         │                             │
         ▼                             ▼
Known Complete Patterns     Recognition Candidates
         │                             │
         └──────────────┬──────────────┘
                        ▼
              Recognition Knowledge
                        │
                        ▼
               Recognition Layer
```

---

# 11. Keuntungan Hybrid Model

## 11.1 Mengurangi Data Duplication

Known pattern dapat berasal dari Character Knowledge.

## 11.2 Candidate Tidak Dipaksa Menjadi Character

Recognition requirement tidak merusak Character Model.

## 11.3 Generic Core Tetap Generic

Generic Core menerima:

```text
Pattern
+
Classification
```

dan tidak perlu mengetahui sumber internal pattern tersebut.

## 11.4 Extensibility Lebih Baik

Script baru dapat menyediakan Recognition Knowledge sendiri.

---

# 12. Pertanyaan yang Masih Harus Dijawab

Phase ini belum dapat menentukan apakah Recognition Knowledge harus menjadi bagian dari public ScriptPack contract.

Masih diperlukan pemeriksaan terhadap:

1. BaseScriptPack saat ini;
2. ScriptPack interface;
3. ScriptPack loader;
4. ScriptPack validation;
5. existing Character Data lifecycle.

Pertanyaan pentingnya:

> Apakah Recognition Knowledge merupakan public capability yang harus diminta Generic Core dari ScriptPack?

Jawaban tersebut belum ditetapkan pada Phase ini.

---

# 13. Preliminary Decision

Berdasarkan evidence saat ini:

> Recognition Knowledge merupakan script-specific knowledge yang dapat dibentuk dari Character Knowledge dan diperluas melalui explicit Recognition Candidate data.

Secara konseptual:

```text
Recognition Knowledge
=
Derived Character Patterns
+
Explicit Recognition Candidates
```
