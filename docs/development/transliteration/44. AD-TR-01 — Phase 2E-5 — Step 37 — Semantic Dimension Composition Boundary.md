# 44. AD-TR-01 — Phase 2E-5 — Step 37 — Semantic Dimension Composition Boundary

## 1. Tujuan

Step 37 bertujuan untuk meneliti bagaimana beberapa **semantic dimensions** dapat digunakan secara bersamaan dalam satu context tanpa menyebabkan semantic boundary antar-dimension menjadi hilang.

Step ini merupakan kelanjutan langsung dari Step 36 yang menunjukkan bahwa:

- Identity
- Occurrence
- Cardinality
- Ordering
- Relationship
- Relationship Identity
- Attributes
- State
- Mutation
- Continuity

merupakan semantic dimensions yang dapat dibedakan.

Step 37 berfokus pada pertanyaan berikutnya:

> Jika semantic dimensions tersebut digunakan secara bersamaan, apakah composition menyebabkan dimensions tersebut melebur, menjadi saling bergantung secara intrinsik, atau berubah menjadi identity, state, lifecycle, atau interpretation bagi dimensions lainnya?

---

## 2. Research Question

> **Apakah beberapa semantic dimensions dapat digunakan secara bersamaan dalam satu context tanpa menyebabkan satu dimension menjadi identity, state, ordering, lifecycle, dependency, atau interpretation bagi dimension lainnya?**

---

## 3. Hypothesis

> Semantic dimensions dapat digunakan secara bersamaan dalam satu context sebagai independent semantic dimensions. Composition tidak dengan sendirinya menyebabkan semantic collapse, intrinsic dependency, identity fusion, lifecycle formation, atau interpretation fusion.

Prinsip awal yang diuji:

> **Composition ≠ Collapse**

Eksperimen berikutnya kemudian memperluas boundary tersebut menjadi:

> **Composition ≠ Dependency**

dan:

> **Dependency ≠ Dimension**

serta:

> **Relationship ≠ Interpretation**

# 5. Step 37-1 — Semantic Dimension Coexistence

## 5.1 Tujuan

Eksperimen pertama menguji apakah berbagai semantic dimensions dapat coexist dalam satu model tanpa otomatis melebur menjadi satu semantic dimension.

Dimensions yang diuji antara lain:

- Identity
- State
- Value
- Ordering
- Attributes
- Request Identity
- Execution Identity
- Cardinality
- Relationship
- Decision

## 5.2 Hasil

**32/32 PASS**

```text
Ran 32 tests in 0.007s
OK
```

Tidak terdapat failure maupun test-harness defect.

## 5.3 Findings

Eksperimen menunjukkan bahwa:

- Identity dapat coexist dengan State.
- Identity dapat coexist dengan Value.
- Identity dapat coexist dengan Ordering.
- Identity dapat coexist dengan Attributes.
- Request Identity dan Execution Identity dapat coexist.
- Relationship dapat coexist dengan Identity dan Attributes.
- Decision dapat coexist dengan Request Identity.
- State change tidak harus menyebabkan Identity change.
- Sequence change tidak harus menyebabkan Identity change.
- Attribute change tidak harus menyebabkan State change.
- Banyak semantic dimensions tidak otomatis membutuhkan composite identity.
- Composite representation tidak sama dengan composite identity.
- Banyak semantic dimensions tidak otomatis menghasilkan lifecycle.

### Principle

> **Composition ≠ Collapse**

Coexistence dalam satu context tidak menyebabkan semantic dimensions kehilangan boundary masing-masing.

# 6. Step 37-2 — Composition vs Dependency

## 6.1 Tujuan

Eksperimen kedua menguji apakah coexistence antara dua semantic dimensions secara intrinsik menyebabkan dependency.

Pasangan yang diuji antara lain:

- Identity ↔ State
- Identity ↔ Value
- Identity ↔ Ordering
- Identity ↔ Attributes
- Request Identity ↔ Decision
- Relationship ↔ Attributes
- State ↔ Decision
- Cardinality ↔ Identity

## 6.2 Hasil

**28/28 PASS**

```text
Ran 28 tests in 0.007s
OK
```

Tidak terdapat failure maupun test-harness defect.

## 6.3 Findings

Eksperimen menunjukkan bahwa:

- Identity tidak secara intrinsik menentukan State.
- State tidak secara intrinsik menentukan Identity.
- Identity dan Value dapat berubah secara independen.
- Identity dan Ordering dapat berubah secara independen.
- Identity dan Attributes dapat berubah secara independen.
- Request Identity dan Decision dapat berubah secara independen.
- State dan Decision dapat berubah secara independen.
- Cardinality tidak menentukan Identity.
- Identity tidak menentukan Cardinality.
- Ordering tidak menentukan Identity.
- Identity tidak menentukan Ordering.

Namun eksperimen juga menunjukkan bahwa dependency **dapat didefinisikan secara contextual**.

Dengan demikian:

> Dependency dapat ada tanpa menjadi intrinsic property dari salah satu dimension.

### Principle

> **Composition ≠ Intrinsic Dependency**

Coexistence tidak cukup untuk menyimpulkan adanya dependency.

Jika dependency memang ada, dependency tersebut harus berasal dari semantic rule, context, atau policy yang relevan.

# 7. Step 37-3 — Dependency as Relationship

## 7.1 Tujuan

Eksperimen ketiga menguji apakah dependency lebih tepat dipahami sebagai intrinsic property dari salah satu dimension atau sebagai relationship antara dua semantic dimensions.

Model yang digunakan:

```text
Dimension A
     │
     │ dependency
     ▼
Dimension B
```

direpresentasikan secara konseptual sebagai:

```text
Dimension A ── Relationship ──> Dimension B
```

## 7.2 Hasil

**27/27 PASS**

```text
Ran 27 tests in 0.006s
OK
```

Tidak terdapat failure maupun test-harness defect.

## 7.3 Findings

Eksperimen menunjukkan bahwa:

- Dependency dapat direpresentasikan sebagai relationship.
- Relationship memiliki source dan target.
- Direction merupakan bagian dari semantic meaning.
- Reverse dependency bukan relationship yang sama.
- Dependency bukan intrinsic property dari source dimension.
- Dependency bukan intrinsic property dari target dimension.
- Dependency tidak menggantikan identity endpoint.
- Dependency tidak membutuhkan identity fusion.
- Dependency tidak membutuhkan composite identity.
- Dependency tidak otomatis menciptakan lifecycle.
- Relationship dapat digunakan kembali dalam beberapa context.
- Perubahan relationship tidak harus menyebabkan perubahan endpoint identity.
- Relationship identity, jika digunakan, tetap berbeda dari endpoint identity.

### Principle

> **Dependency dapat direpresentasikan sebagai Relationship tanpa meleburkan identity atau semantic boundary dari endpoint.**

Dengan demikian:

```text
Dependency ≠ Endpoint Identity
```

dan:

```text
Dependency ≠ Endpoint State
```

Dependency merupakan semantic relationship antara dimensions.

# 8. Step 37-4 — Relationship vs Interpretation

## 8.1 Tujuan

Eksperimen keempat menguji apakah interpretation/evaluation atas sebuah relationship merupakan bagian intrinsic dari relationship tersebut.

Model konseptual yang diuji:

```text
Dimension A
     │
     │ Relationship
     ▼
Dimension B
     │
     └──────────────┐
                    ▼
               Context / Policy
                    │
                    ▼
            Evaluation Result
```

## 8.2 Hasil

**23/23 PASS**

```text
Ran 23 tests in 0.004s
OK
```

Tidak terdapat failure maupun test-harness defect.

## 8.3 Findings

Eksperimen menunjukkan bahwa:

- Relationship dapat exist tanpa evaluation.
- Evaluation Result berbeda dari Relationship.
- Relationship yang sama dapat menghasilkan Evaluation Result yang berbeda.
- Perubahan Evaluation Result tidak harus mengubah Relationship.
- Context dapat mengubah Evaluation Result tanpa mengubah Relationship.
- Policy dapat menjadi input bagi interpretation.
- Policy berbeda dari Relationship.
- Policy berbeda dari Evaluation Result.
- Evaluation bersifat contextual.
- Relationship tetap stabil ketika Evaluation berubah.
- Evaluation tidak mengubah endpoint identity.
- Evaluation Result dapat direpresentasikan sebagai observation.
- Multiple evaluations dapat reference relationship yang sama.
- Evaluation tidak membutuhkan mutation terhadap relationship.
- Evaluation tidak otomatis membentuk lifecycle relationship.

### Principle

> **Relationship ≠ Interpretation**

Relationship dapat menjadi input bagi contextual evaluation tanpa evaluation result menjadi intrinsic property dari relationship.

# 11. Boundary Principles

Step 37 menghasilkan beberapa boundary principles:

### 11.1 Composition ≠ Collapse

Semantic dimensions dapat digunakan bersama tanpa menjadi satu semantic dimension.

### 11.2 Composition ≠ Dependency

Coexistence tidak membuktikan intrinsic dependency.

### 11.3 Dependency ≠ Identity

Dependency tidak menyebabkan identity fusion.

### 11.4 Dependency ≠ State

Dependency bukan state dari endpoint.

### 11.5 Dependency ≠ Ordering

Dependency bukan ordering information.

### 11.6 Dependency ≠ Lifecycle

Adanya dependency tidak otomatis menghasilkan lifecycle.

### 11.7 Dependency may be Relationship

Dependency dapat dipahami sebagai relationship antara dua semantic dimensions.

### 11.8 Relationship ≠ Interpretation

Relationship tidak sama dengan hasil contextual interpretation.

### 11.9 Contextual Interpretation ≠ Relationship Mutation

Perubahan interpretation tidak mengharuskan perubahan relationship.

### 11.10 Semantic Relationship ≠ Endpoint Identity

Relationship antara dua endpoint tidak menyebabkan endpoint tersebut kehilangan atau meleburkan identity masing-masing.

# 13. Implications for AksaraNusantara

Temuan ini relevan bagi architecture AksaraNusantara karena subsystem seperti transliteration dapat memiliki banyak semantic dimensions secara bersamaan.

Contohnya, sebuah execution context secara konseptual dapat melibatkan:

```text
Request Identity
Execution Identity
Operation Identity
Execution State
Ordering
Attributes
Decision
Relationship
Evaluation
```

Kehadiran semuanya dalam satu context tidak berarti semuanya harus digabung menjadi satu object atau satu state.

Sebaliknya, semantic model dapat mempertahankan boundary masing-masing dan membentuk relationship hanya ketika memang terdapat semantic rule yang memerlukannya.

Hal ini mendukung pendekatan research sebelumnya:

> **Semantic distinction does not automatically imply implementation abstraction.**

Dengan demikian, hasil Step 37 juga **tidak memerintahkan pembuatan class atau object baru** dalam production code.

# 17. Final Principle

Kesimpulan utama Step 37:

> **Semantic dimensions may be composed within a context without collapsing into one another. Composition does not intrinsically establish dependency. Dependency may be represented as a relationship between dimensions, while interpretation of that relationship remains contextual and distinct from the relationship itself.**

Versi ringkas:

> **Composition ≠ Collapse ≠ Dependency ≠ Interpretation**

Dengan catatan bahwa simbol tersebut menunjukkan **semantic boundary**, bukan berarti konsep-konsep tersebut tidak dapat berhubungan.
